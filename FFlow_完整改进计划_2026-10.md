# 1. 执行摘要

**总体判断：**FFlow 的分层方向是正确的，已经具备 SDK 雏形，但仓库处于“功能铺开快于稳定化”的阶段。下一阶段不应继续以功能数量为主 KPI，而应先建立正确性、回归测试和大图性能基线。

- 第一优先级：修复/验证无限画布 hit-test、坐标系/origin、删除语义、copyWith 可变更能力、键盘事件消费与 graph invariants。

- 第二优先级：引入 Graph Index 与 Edge Geometry Cache，解决 O(E×N) 重算、重复 Path 计算、animated edge 全层重绘、edge hit-test 全量扫描。

- 第三优先级：补齐复杂节点内部手势隔离、drag threshold、controlled viewport、edge box selection、分场景 auto-pan。

- 第四优先级：在稳定内核上建设 History/Undo/Redo、Clipboard、Helper Lines、布局/路由 adapter 等“编辑器生产力能力”。

- 1.0 前必须完成：API consistency、serialization versioning、错误诊断、跨平台验证、benchmark、文档与 migration 约束。

| **目标维度** | **当前情况**                                                     | **计划目标**                                                 |
|--------------|------------------------------------------------------------------|--------------------------------------------------------------|
| 正确性       | 核心交互已覆盖，但 edge/node/viewport/selection 交叉场景测试稀疏 | 关键交互均有 widget regression test；非法 graph 明确诊断     |
| 性能         | visible culling 可选，但 geometry/index/cache 仍偏线性重算       | 1k 级图可持续交互；5k 级图有明确降级策略与 benchmark         |
| API          | public barrel 已建立，部分 copyWith/nullable/事件语义仍不完整    | 1.0 前冻结一致的 model/controller/change/delete/viewport API |
| 编辑体验     | 拖拽、连接、重连、resize、subflow 已有                           | Undo/Redo、Clipboard、Helper Lines、复杂节点手势隔离补齐     |
| 生态         | 零三方依赖，布局/路由未内置                                      | core 保持轻量，通过 adapter/package 扩展 layout/routing      |

# 2. 当前架构与成熟度判断

Host App / FlowGraphController  
\| nodes / edges  
v  
FFlowCanvas --------------------------  
\| gesture / selection / connection \|  
\| viewport / keyboard / callbacks \|  
+-----------------------------------+  
\| \| \|  
geometry interaction rendering  
\| \| \|  
+------ models / utils -------+

- 优点：models、geometry、interaction、rendering、controllers 已拆层；public API 通过 lib/fflow.dart 统一导出。

- 优点：支持 controlled lists 与 FlowGraphController 两种状态所有权模式；已具备 granular changes。

- 优点：无第三方依赖，适合作为核心 SDK；布局/路由可以后续通过 adapter 扩展。

- 主要债务：Canvas State 仍承担大量“状态源 + gesture coordinator + renderer orchestration + accessibility + hit-test”职责，交互复杂度已经逼近需要内部 session/index/cache 层的临界点。

- 测试债务：当前 test 目录只有 flow_canvas_test.dart 与 flow_graph_utils_test.dart，两者不足以覆盖现有功能面。

## 2.1 当前最值得保留的设计决策

- 保留 typed FlowNode\<T\>；应用层 node data 不侵入 SDK。

- 保留 FlowGraphController，但内部实现升级为带 index/revision 的 graph store。

- 保留 custom nodeBuilder/edgeTypes/connectionLineBuilder；扩展点比硬编码 React API 更适合 Flutter。

- 保留 core 零第三方依赖；ELK/Dagre/libavoid 等作为可选扩展包。

- 保留 controlled / controller 两种模式，但明确单一数据源与事件语义。

# 3. 目标架构与工程原则

| **原则**                 | **落地要求**                                                                                        |
|--------------------------|-----------------------------------------------------------------------------------------------------|
| 正确性优先于 parity      | React Flow 的 API 不做机械翻译；优先保证 Flutter gesture/render tree 下语义正确。                   |
| 坐标系单一真相           | 明确 anchor position、absolute top-left、scene、viewport 四种坐标；转换集中到 geometry/controller。 |
| Graph invariant 显式化   | 非法 graph 不允许静默“尽量算”；至少 debug assert + diagnostics。                                    |
| 事件结果等于真实结果     | delete、reconnect、selection、batch change 回调必须反映最终实际状态。                               |
| 高频路径避免分配         | pointer move / paint / animation tick 中避免反复建 Map、List、Path metrics。                        |
| 扩展能力插件化           | layout、router、collaboration adapter 不侵入 core。                                                 |
| 1.0 前修 API，不背兼容债 | 当前 0.x 是最后适合系统性调整 copyWith / result types / snapshot schema 的窗口。                    |

## 4.1 FFL-001：无限画布 Hit-Test 修复设计

| **验收场景** 节点放置在 x=2000 / x=-1500 / y=1800 等远离初始 viewport 的位置；通过 controller 平移/fitView 回到视区后，节点内部 Button/TextField、Handle、Resize Handle、DragHandle 均可被 Flutter 原生 hit-test 正确命中。 |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

- 先添加失败测试：viewport 800×600；node 放在远坐标；pan/center 后 tap 内部按钮，验证 callback。

- 再测试 nested GestureDetector、FlowPort、resize handle，避免只修 node body。

- 目标实现不要依赖“clipBehavior: Clip.none 即可点击越界 child”的假设；scene 的可交互 RenderBox bounds 必须覆盖实际需要 hit-test 的范围，或将交互 hit-test 完全上移到 viewport overlay 并进行事件路由。

- 若采用 dynamic scene bounds：bounds = union(nodes/edge controls) + viewport padding；处理负坐标时通过 sceneOrigin offset 保持 graph 坐标不变。

- 若采用 overlay hit-test router：节点内部复杂 Widget 的手势将很难代理，因此优先评估“真实 scene bounds + transform”的方案。

## 4.2 FFL-002：坐标系统一规范

Flow coordinates:  
node.position = anchor point  
node.origin = normalized anchor within node  
absoluteTopLeft = absoluteAnchor - Size(width,height) \* origin  
  
Viewport coordinates:  
screen = transform(flow)  
flow = inverseTransform(screen)  
  
禁止：任意 API 将 node.position 隐式当作 top-left。

- 为 geometry 增加明确命名：nodeAbsoluteTopLeft、nodeAbsoluteAnchor、nodeRect、handleAnchor。

- 所有 path/hit-test/selection/minimap/fitBounds 都基于 nodeRect；所有 move/update 均写回 anchor position。

- 加入 origin = (0,0)、(0.5,0.5)、(1,1) + parent/subflow 的参数化单元测试。

## 4.3 FFL-004：删除语义目标

class FlowDeleteResult\<T\> {  
final List\<FlowNode\<T\>\> nodes; // remaining  
final List\<FlowEdge\> edges; // remaining  
final List\<FlowNode\<T\>\> deletedNodes;  
final List\<FlowEdge\> deletedEdges;  
}

- 级联删除 connected edges 必须出现在 deletedEdges。

- 删除 parent 时 children 的“保留并提升到 root”行为要显式写入文档与测试；如未来支持 cascadeChildren，作为 strategy 配置。

- onBeforeDelete 建议未来升级为 FutureOr\<FlowDeleteDecision\<T\>\>，但首轮可先保持同步 API，避免一次改动过大。

# 5. 性能优化计划

**核心目标：**把高频路径从“每次 build/paint/pointer move 重新扫描和重算”切换为“增量 index + revision cache + broad-phase hit-test”。

| **性能热点**          | **现状**                                                            | **优化方案**                                             | **目标**                                      |
|-----------------------|---------------------------------------------------------------------|----------------------------------------------------------|-----------------------------------------------|
| Edge painter map 分配 | paint 已有 byId，但 \_drawEdge 每条 edge 再创建 nodes map           | FlowEdgesPainter 持有/复用 index；edgePathFor 接收 index | 移除 O(E×N) map 构造                          |
| Path 重算             | paint/label/toolbar/semantics/culling/hit-test 多处重复 edgePathFor | FlowEdgeGeometryCache + FlowEdgePathResult               | 单 graph revision 内每条 edge path 仅计算一次 |
| Animated edge         | 任意 animated edge 驱动整个 painter repaint                         | static layer 与 animated layer 分离                      | 静态 edge 不随 animation tick 重画            |
| Edge hit-test         | pointer move 倒序遍历所有 edge + PathMetrics sampling               | bounds/spatial index broad phase，再 narrow phase        | 常见场景候选 edge 数量远小于 E                |
| Graph query           | controller getNode/getEdge/incomers/outgoers 多为 list scan         | FlowGraphIndex                                           | O(1) id lookup；邻接查询按 degree             |
| Visible culling       | 每次 build 对全部 node/edge 求几何                                  | cache bounds + viewport query                            | 大图 viewport 交互稳定                        |

## 5.1 FlowGraphIndex 设计

FlowGraphIndex\<T\>  
nodesById: Map\<String, FlowNode\<T\>\>  
edgesById: Map\<String, FlowEdge\>  
childrenByParentId: Map\<String, List\<String\>\>  
incomingByNodeId: Map\<String, List\<String\>\>  
outgoingByNodeId: Map\<String, List\<String\>\>  
edgeIdsByHandleKey: Map\<FlowHandleKey, List\<String\>\>  
graphRevision: int  
geometryRevision: int

- Controller 模式：controller 每次 setGraph/setNodes/setEdges 重建或增量更新 index。

- Controlled list 模式：Canvas 在 didUpdateWidget / internal publish 后更新内部 index。

- 第一版允许 O(N+E) rebuild，但同一帧只 rebuild 一次；后续再做增量 diff。

## 5.2 Edge Geometry Cache 设计

- Cache key 至少包含 edge.id + source/target node geometry revision + handle configuration + edge geometry fields。

- 缓存：source/target anchor、source/target side、Path、bounds、label position、optional PathMetric。

- Node drag 时只 invalidate 与被移动 node 相连的 edges。

- Selection/color/animated 等纯绘制属性变化不应使 path cache 失效。

## 5.3 性能验收基线

| **数据规模**          | **场景**                       | **必须采集指标**                           | **通过标准（建议）**                               |
|-----------------------|--------------------------------|--------------------------------------------|----------------------------------------------------|
| 100 nodes / 150 edges | drag + zoom + selection        | build/paint 平均、P95 frame、allocations   | 作为功能基线，无明显 jank                          |
| 500 / 800             | 持续 node drag + edge redraw   | UI/Raster frame、GC、path calc count       | 交互主观流畅；无持续高 GC                          |
| 1,000 / 1,500         | onlyRenderVisibleElements=true | P95 frame、visible query、hit-test latency | 目标 60Hz 设备多数帧 \<16.7ms；低配可接受稳定 30Hz |
| 5,000 / 7,500         | pan/zoom + culling             | memory、query cost、frame spikes           | 不崩溃；有明确大图模式/降级策略                    |

| **注意** 上述 frame 数字是目标门槛，不应在尚未建立 benchmark 之前作为“已达成”对外宣传。首轮任务是建立可重复 benchmark，再根据 Windows/Web/macOS 结果调整阈值。 |

# 6. API 与数据模型优化计划

| **工作项**           | **建议**                                                                                                       |
|----------------------|----------------------------------------------------------------------------------------------------------------|
| copyWith             | 所有 immutable model 使用一致 sentinel 方案；允许显式 clear nullable 字段。                                    |
| Result types         | delete/reconnect/validation/fitView 等复杂操作返回结构化结果，不靠多个 callback 拼状态。                       |
| Error/Diagnostics    | FFlowCanvas.onError / FlowDiagnostic；debug 模式附 issue code 与实体 id。                                      |
| Viewport             | 增加 controlled viewport/defaultViewport/onMoveStart/onMove/onMoveEnd；controller 方法支持 animation options。 |
| Interaction policies | nodesDraggable/nodesConnectable/elementsSelectable + per-node override。                                       |
| No-interaction zones | FFlowNoDrag / FFlowNoPan / FFlowNoWheel；用于 TextField/Slider/ScrollView。                                    |
| Threshold            | nodeDragThreshold、connectionDragThreshold，避免 click→drag 误触。                                             |
| Selection            | selectAll(includeHidden)、selection box edge policy、selection context API。                                   |
| Connection           | ongoing connection state 独立模型，提供 isValid/currentTarget 等状态供自定义 UI。                              |
| Snapshot             | schemaVersion + migrations；明确 viewport 与 transient selection 是否默认持久化。                              |

## 6.1 Controlled Viewport 建议 API

FFlowCanvas(  
viewport: viewport, // optional controlled  
defaultViewport: const FlowViewport(...),  
onViewportChange: updateViewport,  
onMoveStart: ...,  
onMove: ...,  
onMoveEnd: ...,  
fitViewOnInit: true,  
fitViewOptions: const FlowFitViewOptions(...),  
)

- Controlled viewport 与 controller 允许共存，但 controller 写入后由 onViewportChange 驱动外部 state；避免内部/外部双写。

- FlowCanvasController.zoomTo/setCenter/fitBounds/fitView 增加 duration/easing/interpolation；返回 Future\<bool\> 或动画句柄。

UpdateNode / UpdateEdge  
ReparentNodes

- 一次 drag 从 pointer-down 到 pointer-up 只提交一个 MoveNodes transaction；pointer move 只更新 preview state。

- History 不放进 FFlowCanvas 内部；Canvas 发出 transaction 或 operation，FlowHistoryController 负责 past/future。

- Clipboard、autosave、collaboration、audit log 都复用同一 operation 模型，避免未来重复设计。

## 7.2 Clipboard 行为规范

- 复制 selected nodes；只复制两端都在复制 node 集合中的 edges，除非显式支持 dangling reference。

- 粘贴时为 node/edge 生成新 ID，并重映射 source/target/parentId。

- 默认粘贴位置相对原图偏移一个固定 viewport 像素等效的 flow delta；连续 paste 累积偏移。

- 父子节点同时复制时保持 parent 关系；只复制 child 时默认变为 root 或提供 policy。

- Clipboard payload 带 schema version，允许跨编辑器实例粘贴。

## 9.2 Graph Validator 测试

- duplicate node id / edge id

- edge source/target 不存在

- sourceHandleId/targetHandleId 不存在或类型不匹配

- 同一 node 内 duplicate handle id

- parentId 不存在、parent cycle、self-parent

- width/height/min/max 非法，NaN/Infinity position/extent

- viewport zoom \<=0、minZoom\>maxZoom、invalid translateExtent

# 结论

**推荐的主线不是“继续补功能”，而是“先稳定内核，再扩展编辑器能力”。** 先完成 M0–M2，FFlow 才具备可持续扩展的基础；随后 M3–M5 的功能将建立在统一的 interaction/session、graph index、geometry cache 与 transaction 模型之上，避免后续反复重构。

| **首个实施建议** 第一个开发 PR 只做 FFL-001 + 对应回归测试，不与性能/API 改造混在一起。第二个 PR 处理坐标/origin 与 keyboard correctness。这样最容易判断风险并保持可回滚。 |
