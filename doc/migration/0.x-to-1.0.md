# 0.x to 1.0 migration notes

This guide records the public API decisions made before a future 1.0 release.
The package remains on its current 0.x version until maintainers intentionally
cut a release.

## Nullable `copyWith` arguments

Passing `null` to nullable `FlowNode.copyWith` or `FlowEdge.copyWith` fields now
clears that field. Omit the argument to keep the previous value. Existing
`clearParentId` and `clearExtent` node arguments remain supported; prefer
`parentId: null` and `extent: null` in new code.

## Delete results

`FlowGraphUtils.deleteElements` and `FlowGraphController.deleteElements` keep
`nodes` and `edges` as the remaining graph, and now also expose
`deletedNodes` and `deletedEdges`. `deletedEdges` includes edges removed because
one of their endpoint nodes was deleted. Canvas delete callbacks report those
actual ids.

## Selection and connection rules

Ctrl+A excludes hidden nodes and edges by default. Set
`selectAllIncludesHidden: true` to include them. Loose mode permits
source-to-source connections; it does not permit target-to-target connections.
Reconnect event `handleId` is nullable instead of using an empty string.

## Snapshot schema

Snapshots now write `schemaVersion: 1`. Unversioned snapshots are treated as
schema 0 and upgraded during decode. Selection is transient and omitted from
JSON by default; pass `includeSelection: true` to persist it. Viewport remains
included. Future schema versions are rejected with a `FormatException`.

## Viewport coordinates

`FlowCanvasController.viewport`, `screenToFlowPosition`, and
`flowToScreenPosition` continue to use graph coordinates even when the canvas
pads its internal scene for hit testing. Prefer these controller APIs over
reading the raw `TransformationController.value` matrix.
